# Массовое управление категориями для выбранных товаров

## Summary
Добавить в текущий bulk-footer товаров новый сценарий массовой работы с категориями без новой параллельной модалки и без переписывания существующего UX.  
Новый сценарий должен переиспользовать:
- текущий bulk-footer снизу
- текущую правую колонку
- текущий category picker, который уже открывается по `+` у одного товара
- текущее финальное подтверждение нижней галочкой

Выбранное поведение:
- bulk-операция категорий работает **вместе** с текущими bulk-чекбокс-действиями
- за одно подтверждение можно применить и обычные bulk-действия, и категорийную операцию

## Key Changes

### 1. Состояние и модель bulk-действий
Расширить текущее состояние bulk-режима в `static/js/products.js`:
- добавить отдельное состояние для операций с категориями
- хранить:
  - `mode`: `none | add | remove | replace`
  - `selectedCategoryIds: Set<number>`
  - флаг открытия picker’а
- не смешивать это состояние с текущими checkbox bulk-actions, а держать рядом с ними

Поведение по умолчанию:
- селектор `Категории` показывает `-`
- `selectedCategoryIds` пустой
- кнопка `+` скрыта, пока не выбран `Добавить`, `Удалить` или `Переместить`

### 2. UI bulk-footer
В существующий footer для выбранных товаров добавить:
- селектор с заголовком `Категории`
- варианты:
  - `-`
  - `Добавить`
  - `Удалить`
  - `Переместить`
- кнопку `+`, которая появляется только если выбран не `-`

Поведение:
- выбор `-` сбрасывает выбранные категории bulk-сценария и закрывает picker, если он открыт
- выбор `Добавить/Удалить/Переместить` не открывает picker автоматически, только показывает `+`
- нижняя галочка подтверждения остаётся общей и применяет:
  - текущие чекбокс-действия
  - bulk-операцию категорий
- кнопка применения должна быть активна, если выбрано хотя бы одно обычное bulk-действие **или** валидная категорийная операция

### 3. Переиспользование category picker
Не создавать новый picker. Переиспользовать текущий `openCatPicker()` / существующий overlay правой колонки, но расширить его контекстом bulk-режима.

Нужно добавить bulk-контекст открытия:
- picker открывается не из товара, а из bulk-footer
- стартовое выделение всегда пустое
- пользователь выбирает категории заново
- после `Сохранить` в picker:
  - значения сохраняются только в bulk-state
  - категории не пишутся сразу в товары
  - picker закрывается
- после `Отменить`:
  - bulk-state категорий не меняется
  - picker закрывается

Для bulk-режима в picker:
- `Все товары` нельзя выбирать
- логика parent/child должна остаться такой же, как сейчас у одиночного picker:
  - выбор дочерней категории может подтягивать родителя
  - снятие родителя снимает его дочерние элементы
- в правой колонке никакие категории не должны быть предвыбраны из товаров

### 4. Применение к товарам
При нажатии нижней галочки:
- сначала собрать текущий список выбранных товаров
- затем для каждого товара получить его текущие категории
- затем вычислить новые `category_ids` по выбранному режиму

Правила:
- `Добавить`
  - добавить выбранные категории к уже существующим
  - если категория уже есть, оставить как есть
- `Удалить`
  - удалить выбранные категории из текущего набора
  - если категории не было, ничего не менять
- `Переместить`
  - удалить все текущие категории, кроме системной `Все товары`
  - записать только новые выбранные категории
  - `Все товары` не добавлять и не передавать как выбранную пользователем категорию

Технически:
- переиспользовать текущий PATCH `/api/prod_products/:id` с `category_ids`
- не вводить новый backend endpoint, если текущего PATCH достаточно
- итоговый `category_ids` должен передаваться уже полностью рассчитанным списком для конкретного товара
- после успешного применения обновлять:
  - `state.products`
  - кэш деталей товара
  - правую колонку для активного товара
  - видимость строки в текущей категории, если после изменения товар больше не принадлежит текущему списку

### 5. Совместная работа с текущими bulk-чекбоксами
Оставить текущий popup с чекбоксами без дублирования.

Порядок применения в одном подтверждении:
- для товара сначала вычислить итоговые `category_ids`, если выбран режим категорий
- затем отправить один PATCH на товар с объединённым payload:
  - обычные bulk-поля (`is_active`, `site_visibility`, `stock`, `fulfillment_mode`)
  - `category_ids`, если выбрана bulk-операция категорий
- если для конкретного товара категорийная операция не меняет категории, но есть обычные bulk-поля, PATCH всё равно выполняется
- если обычных bulk-полей нет и категорийная операция не меняет категории, товар пропускается без ошибки

После успешного применения:
- сбросить category bulk-state
- сбросить текущие checkbox bulk-actions
- закрыть bulk popup
- снять выделение товаров так же, как делает текущий сценарий
