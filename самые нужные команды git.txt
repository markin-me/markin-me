
ОБЩИЕ КОМАНДЫ (подходят ВСЕГДА)
| Команда                | Что делает                  | Результат                |
| ---------------------- | --------------------------- | ------------------------ |
| `git pull`             | Забрать обновления с GitHub | `Already up to date`     |
| `git add .`            | Подготовить изменения       | Без вывода               |
| `git commit -m "msg"`  | Создать коммит              | `[main hash]`            |
| `git push`             | Отправить изменения         | Успешный push            |
| `git status`           | Проверить состояние         | Чисто / список изменений |
| `git log --oneline -5` | Последние коммиты           | Список коммитов          |


Создать НОВЫЙ проект с нуля и загрузить на GitHub
| Команда                                                     | Что делает           | Ожидаемый результат                |
| ----------------------------------------------------------- | -------------------- | ---------------------------------- |
| `mkdir new-project`                                         | Создать папку        | Папка создана                      |
| `cd new-project`                                            | Зайти в неё          | Путь к new-project                 |
| `git init`                                                  | Инициализировать git | `Initialized empty Git repository` |
| `git branch -M main`                                        | Назвать ветку main   | Без ошибок                         |
| `git remote add origin https://github.com/USER/NEWREPO.git` | Привязать GitHub     | Команда без вывода                 |
| `git status`                                                | Проверка             | `No commits yet`                   |
| `git add .`                                                 | Добавить файлы       | Команда без вывода                 |
| `git commit -m "init"`                                      | Первый коммит        | `[main …] init`                    |
| `git push -u origin main`                                   | Загрузить на GitHub  | Успешный push                      |

| `git status`                                                    | Проверка состояния                    | `working tree clean`           |


Получить изменения с GitHub после того, как запушил свои изменения
| Команда                | Что делает                                    | Ожидаемый результат                    |
| ----------------------- | --------------------------------------------- | -------------------------------------- |
| `git pull`              | Забрать обновления с GitHub                   | `Already up to date` или обновления    |
| `git pull origin main`  | Забрать обновления из ветки main              | Обновления загружены                   |
| `git pull --rebase`     | Забрать обновления с rebase (чистая история)  | Коммиты применены поверх удалённых     |
| `git pull --no-rebase`  | Забрать обновления с merge (создаёт merge-коммит) | Merge-коммит создан                   |
| `git fetch`             | Только скачать изменения (не применять)       | Изменения скачаны, но не применены    |
| `git fetch origin`      | Скачать изменения из origin                   | Изменения скачаны                      |
| `git merge origin/main` | Применить скачанные изменения (после fetch)   | Изменения применены                    |

💡 **Совет:** Если работаете в команде, всегда делайте `git pull` перед началом работы, чтобы получить последние изменения от коллег.


РАБОТА В КОМАНДЕ: Что происходит при параллельных изменениях

📖 Сценарий: Друг создал новую страницу, вы изменили свои файлы

ШАГ 1: Начальное состояние
├─ У вас: файлы A, B, C
└─ У друга: файлы A, B, C (одинаковые)

ШАГ 2: Параллельная работа
├─ ВЫ: изменили файл A, создали файл D
└─ ДРУГ: создал новую страницу (файл E), изменил файл B

ШАГ 3: Вы делаете push ПЕРВЫМ
├─ `git add .` → подготовка изменений
├─ `git commit -m "изменения"` → коммит создан
└─ `git push` → ✅ УСПЕШНО отправлено (ваши A, D на GitHub)

ШАГ 4: Друг делает push ПОСЛЕ ВАС
├─ `git add .` → подготовка изменений
├─ `git commit -m "новая страница"` → коммит создан
└─ `git push` → ❌ ОШИБКА: "Updates were rejected"
   └─ Причина: на GitHub уже есть ваши изменения, которых нет у друга

ШАГ 5: Друг делает pull (получает ваши изменения)
├─ `git pull` → скачивает ваши файлы A, D
├─ Git автоматически объединяет:
   │  ├─ Ваш файл A (изменённый) + файл B друга (изменённый) = OK
   │  ├─ Ваш файл D + файл E друга = OK (разные файлы)
   │  └─ Результат: у друга теперь A, B, C, D, E
└─ `git push` → ✅ УСПЕШНО отправлено (теперь на GitHub: A, B, C, D, E)

ШАГ 6: Вы делаете pull (получаете изменения друга)
├─ `git pull` → скачивает файл E (новая страница)
├─ Git автоматически добавляет:
   │  └─ Результат: у вас теперь A, B, C, D, E
└─ ✅ ВСЁ СИНХРОНИЗИРОВАНО

⚠️ КОНФЛИКТЫ (если оба изменили ОДИН И ТОТ ЖЕ файл):
├─ Если вы изменили файл A, и друг тоже изменил файл A
├─ `git pull` покажет: "CONFLICT in file A"
├─ Git пометит конфликт в файле:
   │  <<<<<<< HEAD
   │  ваш код
   │  =======
   │  код друга
   │  >>>>>>> branch
├─ Нужно вручную выбрать, что оставить, или объединить оба варианта
└─ После исправления: `git add .` → `git commit` → `git push`

✅ ПРАВИЛЬНЫЙ ПОРЯДОК РАБОТЫ:
1. Перед началом работы: `git pull` (получить последние изменения)
2. Делаете свои изменения
3. `git add .` → `git commit -m "описание"` → `git push`
4. Если push не прошёл: `git pull` → разрешить конфликты → `git push`

💡 **Золотое правило:** Всегда делайте `git pull` ПЕРЕД началом работы и ПЕРЕД push!
