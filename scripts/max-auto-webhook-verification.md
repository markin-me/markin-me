# MAX Auto Webhook — 17.11.2026

Рабочая ветка: `feat/messenger-auth`. Все изменения текущей доработки локальные.

## Подключение

Тенант вводит только токен MAX и нажимает существующую кнопку «Сохранить».
Имя бота определяется через GET /me. Поле имени доступно только для чтения.
Обязательный флаг MAX_AUTO_WEBHOOK_ENABLED удалён.

Публичный origin определяется из серверной конфигурации CRM:
MAX_WEBHOOK_BASE_URL, ADMIN_BASE_URL, APP_BASE_URL, PUBLIC_BASE_URL, SITE_BASE_URL;
если URL не задан, используется первый публичный домен из ADMIN_ALLOWED_HOSTS.
Адреса localhost и HTTP не принимаются. Host из входящего запроса не используется.
Конкретный домен в коде не прописан. Свой домен тенанту не нужен.

Сохранение токена будит существующий worker, не ожидая следующего фонового интервала.
Worker проверяет токен, доступность публичного endpoint этой CRM и подписки MAX,
регистрирует отсутствующую подписку и повторно проверяет её наличие.
Фоновая проверка запускается также при старте CRM; рабочая подписка проверяется раз в 5 минут.
Повторы временных ошибок используют MySQL next_attempt_at, exponential backoff и Retry-After.
Недействительный токен не проверяется бесконечно.

## Токен и интерфейс

GET настроек возвращает маску той же длины, что и сохранённый токен.
Для проверенного ранее токена из тестовой БД это 84 символа.
Отправка маски сохраняет реальный токен; прежняя маска из восьми звёздочек также поддерживается.
Имя, полученное worker из MAX, не затирается устаревшим значением формы.
Для нового токена прежнее имя очищается до автоматического определения нового бота.
Поля ручной настройки webhook и отдельная кнопка регистрации не добавлялись.
Ошибки настройки публичного адреса, секрета и сертификата отображаются отдельно.

## Изоляция и совместимость

Один токен использует один bot-scoped endpoint независимо от количества тенантов.
Регистрацию сериализует MySQL GET_LOCK; сравнение токенов учитывает регистр.
Входящие события проверяются по секрету и передаются существующему dispatcher.
Старый и новый маршруты MAX используют единое пространство дедупликации;
учитывается история обработки старых tenant-scoped событий.
Удаляется только ранее зарегистрированный данным worker URL и только если токен
не используется другими тенантами, включая неактивных.
Бизнес-логика MAX авторизации и Telegram On-Demand Polling не переписывалась.
